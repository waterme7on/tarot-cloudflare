# Tarot Tools — Tarot Card Generator on Cloudflare

Free, no-signup tarot card generator with paid AI-assisted deep reports. Everything except card payments runs on Cloudflare: Workers (Astro SSR + API), D1, KV, R2, Queues, Workflows, Workers AI + AI Gateway, Turnstile, Analytics Engine, Cron Triggers, Access and Workers Builds. Waffo Pancake (merchant of record) is the only external service (payment rail only).

Implements `Tarot-Cloudflare-完整实施方案.md` (v1.0, 2026-11-06).

## Visuals

All 78 cards have original AI-generated illustrations (ukiyo-e + colored sumi-e direction borrowed from [holo-card-studio](https://github.com/EverettFish/holo-card-studio)) rendered through a Three.js holographic card (`src/components/HoloCard.tsx`): spectrum foil, light sweep, sparkle stars, pointer/gyro tilt, gold edges and a flip reveal on draw. Source PNGs live in `artwork/raw/` (git-ignored); `npm run artwork` resizes them into `public/cards/*.webp` + thumbnails and writes `src/data/artwork.json`.

## Stack

- Astro 5 + `@astrojs/cloudflare` (SSR on Workers, static assets for SEO pages)
- React islands only for the draw tool, result, share and report views
- D1 (cards, readings, reports, events, backups), KV (rate limits, webhook dedupe), R2 (reports, share images, D1 backups)
- Queues → Workflows → Workers AI (via AI Gateway) for paid reports, with rules-engine fallback
- Turnstile on draw and checkout, KV fixed-window rate limiting, HMAC-signed short-lived R2 links
- Cron: 10-min report timeout/refund sweep, daily cleanup + event aggregation, weekly D1→R2 backup
- `/admin` protected by Cloudflare Access (JWT verified in middleware)

## Local development

```bash
npm install
cp .dev.vars.example .dev.vars        # Turnstile test keys work out of the box
npm run db:migrate:local
npm run db:seed:local
npm run build && npx wrangler dev     # http://localhost:8787
```

`astro dev` also works for page work, but Queues/Workflows/cron need `wrangler dev`.

Trigger cron locally: `curl "http://localhost:8787/cdn-cgi/handler/scheduled?cron=0+3+*+*+*"`.

## Cloudflare provisioning (one time)

```bash
npx wrangler login
npx wrangler d1 create tarot-db                 # paste database_id into wrangler.jsonc
npx wrangler kv namespace create CACHE          # paste id
npx wrangler r2 bucket create tarot-media
npx wrangler queues create tarot-reports
# repeat with -preview suffixes for the preview env

npx wrangler d1 migrations apply tarot-db --remote
npm run db:seed:prod

npx wrangler secret put TURNSTILE_SECRET_KEY
npx wrangler secret put PUBLIC_TURNSTILE_SITE_KEY
npx wrangler secret put WAFFO_MERCHANT_ID       # Dashboard → API & Development
npx wrangler secret put WAFFO_PRIVATE_KEY < key.pem   # production API key (PEM, PKCS#8)
# Dashboard → store → Settings → Webhooks: add https://<site>/api/v1/webhooks/waffo (order.completed, refund.succeeded, refund.failed)
# and paste the Production "Webhook Public Key" + product IDs into wrangler.jsonc vars
npx wrangler secret put IP_HASH_SALT            # openssl rand -hex 32
npx wrangler secret put TOKEN_SIGNING_KEY       # openssl rand -hex 32
npx wrangler secret put CF_ACCESS_TEAM_DOMAIN   # e.g. yourteam.cloudflareaccess.com
npx wrangler secret put CF_ACCESS_AUD           # Access application AUD tag for /admin
```

Dashboard items: create the AI Gateway named `tarot-gateway`; add a Turnstile widget; create an Access application for `/admin/*`; enable Web Analytics on the zone; add WAF managed rules + rate-limiting rules for `/api/v1/*`; set a Workers AI daily spend limit; create a Notification for Worker error rate and queue backlog.

Update `SITE_URL` in `wrangler.jsonc` and `public/robots.txt` to the production domain.

## Deploy

Connect the GitHub repo in Cloudflare → Workers & Pages → Workers Builds:

- Build command: `npm run build`
- Deploy command: `npx wrangler deploy`
- Production branch: `main`; PRs get preview deployments (`--env preview`).

Manual: `npm run deploy`. Before each production release run `npm run backup` (D1 export → R2).

## API

| Method | Path | Notes |
|---|---|---|
| POST | `/api/v1/draw` | Turnstile, 10/min per IP, idempotency key |
| GET | `/api/v1/readings/{token}` | public reading, no-store |
| POST | `/api/v1/report/checkout` | creates report + Waffo checkout session |
| POST | `/api/v1/webhooks/waffo` | RSA signature verified, deduped in KV, enqueues report |
| GET | `/api/v1/report/{token}` | status + 10-minute signed file URL |
| GET | `/api/v1/files/{key}` | serves R2 object (signed for reports) |
| GET | `/api/v1/share/{token}.svg` | OG/share image (no question text) |
| POST | `/api/v1/events` | whitelisted product events → Analytics Engine + D1 |
| GET | `/api/v1/health` | |

## Content rules

See `scripts/validate-content.ts`. Every card page needs unique title/description, Upright/Reversed/Love/Career/Money/Yes-or-No sections, 600–1100 words, 2–4 related cards, ≥1 spread, ≥1 question, updatedAt and author. Entertainment only; no medical/legal/financial advice.
